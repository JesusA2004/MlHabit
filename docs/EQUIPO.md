Lectura obligatoria junto con `docs/ARQUITECTURA.md`. Cada módulo es dueño EXCLUSIVO de sus archivos; para tocar archivos de otro módulo, no se edita: se usa el contrato descrito aquí.

## Contratos entre módulos (URLs/nombres fijos)

- **crm → projects**: botón "Crear proyecto" en el detalle del prospecto hace `POST /admin/prospectos/{lead:uuid}/proyecto` (ruta `admin.proyectos.desde-prospecto`, la implementa **projects**: crea Project desde Lead, mueve Lead a `design`/`won` según corresponda, redirige al proyecto).
- **crm → visits**: botón "Agendar visita" en el prospecto lleva a `GET /admin/visitas/crear?prospecto={lead uuid}` (**visits**). Enlace al cliente para pagar su visita: `GET /agendar-visita/{lead:uuid}` firmado (`URL::signedRoute('public.visita.inicio', ['lead' => uuid])`, **visits**). La página de gracias de `/solicitar` enlaza a la reserva de asesoría (crm) y a `/agendar-visita` público abierto (`public.visita.abierta`, **visits**) que pide CP primero.
- **visits → projects**: `App\Events\PaymentConfirmed` con `payment.concept`: `visit_fee` lo maneja visits (visita pagada + VisitCredit si aplica); `deposit`, `installment`, `balance` los maneja **projects** con un listener (contrato/anticipo → `ProjectStatus::Authorized`). `PaymentRefunded` → visits invalida/ajusta VisitCredit; projects revierte si fuera anticipo.
- **visits expone** `App\Payments\PaymentService` con: `createIntent(Customer, PaymentConcept, Money $amount, string $description, array $links /* site_visit_id|project_id|contract_id */, string $idempotencyKey): Payment`, `chargeCard(Payment, string $tokenId, string $deviceSessionId, Request): Payment` (maneja 3DS), `recordManual(Payment|array, method, reference, User $actor): Payment` (requiere `payments.record`), `refund(Payment, Money, string $reason, string $idempotencyKey, User): Refund`. Enum `App\Enums\PaymentConcept` (visit_fee, deposit, installment, balance, other), `PaymentStatus` (pending, processing, paid, failed, cancelled, partially_refunded, refunded, disputed), `PaymentMethod` (card, transfer, cash, other). Componente Vue `resources/js/components/payments/OpenpayCardForm.vue` (props: paymentUuid, amount, chargeUrl) reutilizable desde el portal para pagar anticipos: la URL de cobro del anticipo la implementa projects llamando a `PaymentService`.
- **VisitCredit** (tabla de visits): projects lo APLICA al crear el contrato: dentro de la transacción, `VisitCredit::where(site_visit… del cliente/proyecto)->where('status','available')->lockForUpdate()`, valida vigencia, marca `applied` + `contract_id` (UNIQUE garantiza una sola aplicación). Contrato: `deposit_amount = contract_amount × deposit_percent`, `deposit_due_amount = max(0, deposit_amount − visit_credit_amount)`; el total del contrato NO cambia.
- **projects ↔ ops**: ops lee `Project`, `DesignVersion` (solo emite fabricación si `technical_approved_at` no es nulo) y transiciona el proyecto con `ProjectWorkflow` (fabrication, ready_to_install, installation_scheduled, installing, quality_review, punch_list, completed). La pestaña de operación del proyecto (detalle en admin de projects) muestra órdenes leyendo los modelos de ops si existen (`class_exists` no es necesario: los modelos existirán).
- **Portal**: projects es dueño de `PortalLayout` de navegación y páginas; ops agrega `/portal/instalaciones/{order}` (conformidad del cliente) y projects enlaza ahí desde la cronología/proyecto.
- **Técnico**: projects es dueño de `/tecnico` (Hoy) y `/tecnico/visitas/*`; ops de `/tecnico/instalaciones/*`. "Hoy" lista ambas cosas (lee InstallationOrder).
- **Uploads privados**: cualquiera autenticado y activo puede iniciar una sesión de subida `visibility=private` (`/admin/multimedia-sesiones` lo renombra web a `/subidas` si conviene; ver `useChunkedUpload.ts`), pero el archivo queda huérfano hasta vincularlo con `attachMedia` en un endpoint del módulo que valide la Policy de la entidad. Un job de web purga privados huérfanos > 24 h.
- **Público sin sesión** (fotos opcionales en `/solicitar`): crm sube directo con `MediaUploadService::upload($file, 'privado/prospectos', MediaVisibility::Private)` con validación MIME/tamaño y rate limit.
- **Notificaciones**: cada módulo crea sus `Notification` (mail + database) en `app/Notifications/<Modulo>/`. platform hace el tema visual del correo (vistas `resources/views/vendor/mail`) y el centro de notificaciones.

## Seeders

Cada módulo crea sus seeders con datos de CONFIGURACIÓN necesarios (nunca datos de negocio inventados) y lista su nombre en su informe; el coordinador los agrega a `DatabaseSeeder`. Factories para todo modelo propio.

## Pruebas por módulo

Base aislada: `DB_DATABASE=mlhabit_test_<modulo> php artisan test --compact tests/Feature/<Modulo>` (bases ya creadas: web, crm, visits, projects, ops, platform). Herramientas: `vendor/bin/pint --dirty`, `vendor/bin/phpstan analyse <tus rutas>`, `node_modules/.bin/vue-tsc --noEmit` (filtra errores de tus archivos), `php artisan wayfinder:generate` (si falla por concurrencia, reintenta). No ejecutar `npm run build` ni `migrate:fresh` sobre la base `mlhabit` principal.
